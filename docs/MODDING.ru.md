# Как сделать мод

[English](MODDING.md)

Моды лежат в папке `mods` рядом с `MatrixGame.exe`, каждый в своей папке. Игра читает их при запуске. Для мода только из данных пересобирать игру не нужно; мод с кодом — это DLL, собранная под этот движок.

## Папка мода

```
mods/
  mymod/            имя папки — это id мода: a-z, 0-9, _ и -
    mod.txt         что это за мод (обязательно)
    data.txt        значения поверх данных игры на бой (боевой мод, необязательно)
    mymod.dll       его код (необязательно; Dll= в mod.txt)
    ...             всё остальное, что он читает (модели, текстуры)
```

Лобби сравнивает все файлы всех боевых модов в папке (имена и содержимое). У всех игроков боя должны быть одинаковые файлы, иначе лобби покажет мод как отсутствующий или другой, и бой не начнётся. По сети моды не передаются: автор отправляет папку, каждый игрок проверяет её и кладёт в `mods`.

## mod.txt

UTF-8 (или UTF-16 с BOM). Одна строка `Имя=значение`; строки, начинающиеся с `#` или `//`, — комментарии.

| Строка | Значение |
| --- | --- |
| `Name=`, `NameEn=` | Название мода на русском и английском (без английского берётся русское). |
| `Description=`, `DescriptionEn=` | Описание; несколько строк складываются, каждая — отдельный абзац. Показывается в окне «i» мода. |
| `Author=` | Автор. |
| `Kind=battle` или `Kind=personal` | Боевой мод меняет сам бой; личный — только то, что видит один человек и как он играет (см. ниже). |
| `Default=on` | Включён у того, кто ещё ничего не выбирал. |
| `Dll=mymod.dll` | Его код, в папке мода. Для мода только из данных не нужен. |
| `Dependence=a, b` | Моды, без которых он не работает: лобби предложит их включить. |
| `Conflict=a, b` | Моды, с которыми он несовместим: бой с обоими не начнётся. |
| `Key.<Id>=<клавиша>\|<по-русски>\|<по-английски>\|<группа>` | Клавиша мода на странице клавиш в настройках, например `KEY_F2`; английский текст и группу можно не писать. Выбор человека хранится в `CFG\keys.txt` как `<мод>.<Id>`. |
| `Setting.<Id>=<значения через запятую>\|<по умолчанию>\|<по-русски>\|<по-английски>` | Настройка на странице модов; хранится в `CFG\mods.txt` как `<мод>.<Id>`. |
| `ShaderValue=a, b` | Числа, которые мод передаёт наборам шейдеров: его код задаёт число так: `ShaderPacks::set_mod_value("a", 0.5f)` (обычно от 0 до 1), набор читает его как `MOD_A` (docs/SHADERS.ru.md). Наш «Шутер» передаёт `Shooter`: насколько вид уже вошёл в робота или турель. |
| `Switches=` | Переключатели наших модов в движке (см. ниже); не для нового мода. |

## Боевые и личные моды

В общем бою каждый компьютер считает весь бой и раз в секунду сверяет его с остальными. Боевой мод меняет сам бой, поэтому он должен быть у всех; боевые моды выбирает хозяин. Личный мод может менять камеру, отрисовку, интерфейс и клавиши, может отдавать приказы своей стороне так, как мог бы сам игрок; менять бой он не должен, иначе этот игрок сразу рассинхронизируется. Переключатель хозяина в лобби «Только встроенные личные моды» не пускает чужие личные моды (их файлы сверяются с файлами релиза).

## Мод из данных: data.txt

Боевой мод может нести `data.txt` в формате данных самой игры (блоки `CFG\robots.dat`). Перед каждым боем игра накладывает `data.txt` всех включённых боевых модов поверх своих данных и заново читает значения. Перед следующим боем она их снимает.

- `Имя=значение` задаёт параметр игры с этим именем в этом блоке или добавляет его.
- `Имя { ... }` заходит в блок игры с этим именем или добавляет его.
- `ReplaceBlocks=1` в блоке: блоки мода в нём заменяют все блоки игры в нём; параметры игры там остаются.
- `%MOD%` в значении — папка мода (`%MOD%\head.vo`).

`data.txt` личного мода не читается. Меняются только значения, которые игра читает на бой: урон оружия, дальность, перезарядка и нагрев, цены, время, характеристики роботов, подкрепления. Два наших мода состоят только из данных и годятся как примеры:

- `mods\sr2\data.txt` (Баланс КР2) задаёт отдельные значения в `Weapons`, `Price` и `Chars`:

  ```
  Weapons {
      Cooldown {
          WEAPON_GUN=500
      }
  }
  ```

- `mods\sky\data.txt` (Помощь с небес) заменяет шаблоны подкреплений (`FlyerOrders { GiveBot { ReplaceBlocks=1 ... } }`). Ещё он задаёт, сколько приносит вызов: `CallPoints=150` (в игре 100). Его самочинящиеся роботы носят `SelfRepairHead=%MOD%\reparator.vo` с текстурой игры `SelfRepairHeadTexture=`.

## Мод с кодом: DLL

DLL-мод собирается с заголовками этого движка и линкуется с `PBOEngine.dll`, поэтому видит классы и глобальные переменные движка напрямую. В одном из его исходников:

```cpp
#include "ModApi.hpp"

void init(ModApi::Context &mod) {
    // клавиши (mod.on_key), настройки (mod.setting), строки лога (mod.log), папка (mod.folder)
}

PBO_MOD_ENTRY("mymod", init)
```

`ModApi::Context` (`MatrixGame/src/ModApi.hpp`) даёт моду его id и папку, включён ли он сейчас, его клавиши и настройки, строку лога и обработчик клавиш. Чтобы собрать мод, положите его рядом с нашими (`MatrixGame/mods/<id>/<id>.cpp` и `mod.txt`) и добавьте id в `MATRIXGAME_MODS` в `MatrixGame/CMakeLists.txt`. Сборка положит `mods/<id>/<id>.dll` рядом с EXE.

- **Версия игры.** В DLL записан id движка (`PBO_ENGINE_ID`), и игра загружает её только для той же сборки. «Built for another version of the game» в `logs\test.log` значит: пересоберите мод под эту версию. С каждым релизом игры моды нужно пересобирать.
- **Хуки.** Движок спрашивает наши моды в местах, которые они меняют (`MatrixGame/src/ModHooks.hpp`): как поворачивает ракета, что делает ремонтный завод и так далее. Каждый хук принадлежит одному из наших модов и работает, пока включён переключатель этого мода (`Switches=`), так что новому моду хуки пока не открыты. Новые хуки добавляются, когда они нужны моду: попросите, назвав место в движке.
- **Лицензия.** DLL, собранная с движком, — производная от него работа: она под GPL (версии 2 или более поздней), как и движок.

## Если что-то пошло не так

- `logs\test.log` рядом с EXE говорит, какие моды загрузились, какие данные наложены («Battle mods' data: ...») и почему мод был пропущен.
- Падение, закрывшее игру, записывается в `logs\crash.txt` рядом с EXE: место как модуль+смещение и цепочка вызовов.
